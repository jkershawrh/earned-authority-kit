Three bounded engineering milestones

M1 · Executable local fixture

GREEN

Fixture behaviors, schemas and durable local evidence.

M2 · Connected canonical services

AMBER

Pinned local stack and specifically executed lifecycle/fault cases.

M3 · Deployable local reference kit

GREEN

Fresh same-host reconstruction and full persistent restart.

Same host and a disposable model registry. A passing milestone covers its named checks. It does not pass every broader G0–G4 acceptance criterion.

Broader dependency gates

G0 · Shared contract

Agree producer/consumer fixtures, ownership, bindings and signed fields.

G1 · Parallel components

Authority · Qualification · Fenced execution · Durable evidence

G2 · Connected lifecycle

Execute the whole arc and preserve an unaffected second skill.

G3 · Evaluation

Held-out comparisons, uncertainty, failure injection and stopping rules.

G4 · Repeatable deployment

Fresh setup, recovery, then a tested Red Hat reference profile.

Development methods

TDD · Test-driven

Capture a failing behavior, make the smallest correction, retain the regression.

EDD · Evaluation-driven

Freeze metrics, baselines and held-out cases before measuring benefit.

CDD · Contract-driven

Shared schemas and producer/consumer compatibility, including rejection cases.

BDD · Behavior-driven

Given/When/Then scenarios must execute against observable state changes.

Evidence supports all four. CUT terminology remains unconfirmed. The business-value evaluation is still unrun: choose the target, human baseline and sample adequacy before scoring.
