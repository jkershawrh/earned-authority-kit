# Actual human comparator runbook proposal

Status: PLANNED, operator unassigned. This is a proposed procedure for real human participation, not measured human work and not a scored manual baseline.

Use the same assigned requests, starting states, public support observations, authority rules, fault schedules and scoring deadlines as the automatic arms. The human chooses whether to request exact qualification/grant, initiate the bounded registry action, or hold/refuse. A script may enforce the chosen action and collect timings; it may not replace the choice and be labelled human.

Before scoring, name the operator and record relevant experience, training, the allowed runbook/tools, and assistance. Counterbalance arm order and operator assignment. Avoid exposing private query labels or allowing a participant's repeated exposure to a paired case to become undeclared knowledge. Disclose any case reuse.

For each assigned task, capture assignment time, active handling start/stop intervals, choices, intervention count, requested exact bindings, command/attempt ID, authority revision, terminal outcome, and independent readback. Separate active handling time from waiting. Preserve failed, refused, interrupted and timed-out requests in the denominator. Leave missing measurements absent; do not infer zero minutes or interventions from a deterministic trace.

Keep identical authority checks at the mutation boundary. An operator's approval cannot bypass revoked/expired/mismatched permission, missing qualification or a forbidden scope. The independent grader uses actual committed state and the original query, not the operator's success claim.

Stop on an unauthorized commit or invalid grading. Seal each query before any permitted next support phase. The sequential schedule, deadlines, attempt budgets, value threshold and sample design must be fixed and reviewed before held-out execution. The current pilot CLI has no manual or confirmatory execution mode. No human has performed this runbook in the delivered evidence.
